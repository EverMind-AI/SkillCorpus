**Known host limitation.** Hermes caps an external memory provider's whole
`prefetch` at **8 seconds**, in the host, whatever `timeout_s` the plugin
config asks for. The rewriter is one model call and against this deployment
spends more than that, so under the host default `auto` delivers nothing. On an
unmodified Hermes with a reasoning model **`auto` is effectively unusable**:
either raise the host cap or set `rewrite: false`.

**2.0 needs a different package, not a flag.** The `before_prompt_build` hook
the 1.x plugin is built on never fires under `agent --local`; through the
gateway it fires but `prependContext` is dropped. `plugin-openclaw2` occupies
the context-engine slot instead.

**The gates fail silently, and one is easy to misplace.** `auto` is inert,
without an error, unless
`plugins.entries.skillsearch.hooks.allowConversationAccess`,
`...hooks.allowPromptInjection` and `plugins.slots.contextEngine` are all set.
The two grants belong to the **plugin entry**; written in a top-level `hooks`
block the host rejects the whole config as `Unrecognized keys`, which at least
fails loudly. `--accept-capabilities` covers run-level acceptance where a
launcher needs it. The host also requires
`info.transcriptSemantics.currentTurnFence` and `turnAdvancementIdempotency`
**together with** a real `commitTurn` before it trusts durable turn
advancement.

**Instruction-shaped fixtures do not work on this host.** A skill body that
tells the model to reply with a token is read as prompt injection and refused.
That is why the corpus carries facts and the prompts ask questions those facts
answer.

**The lifecycle fix is what made this row possible.** Through `e337cfa` the MCP
entry point served stdin only in `on_demand`, so with `mode: auto` the
statically declared server started and exited 0 immediately. The manifest
cannot withdraw a declared MCP server, so the host kept launching one that
died — a failed entry or restart churn beside a hook path that was working
fine. It now serves in both modes and answers `tools/list` with an empty array
in `auto`. The earlier maintainer run predated this and is superseded.

What the automated suite adds, and what it does not: the shipped
`dist/mcp.mjs` is spawned as a real child process and spoken to in JSON-RPC
over a pipe, returning a skill through the real engine; the process stays up in
**both** modes; `tools/list` answers per mode; a `tools/call` arriving in `auto`
is refused. That is a **spawned-process test, not a host test** — it proves the
bundle speaks the protocol, not that WorkBuddy launches it. The manual run is
what covers the launch. Neither reads the `mcpServers` **declaration shape** off
the host directly: it wants an absolute `args[0]`, the manifest writes
`${CODEBUDDY_PLUGIN_ROOT}/dist/mcp.mjs`, and `expandBracedEnvReferences` exists
in the spawn path but was never observed being applied to MCP args. On-demand
passing is strong circumstantial evidence that it expands — the server has to
start for the tool to appear at all.

## P4 — Mode exclusivity, and an unrecognised mode

Exclusivity is read off the P1–P3 runs above: in every `auto` run the tool was
absent and uncalled, in every `on_demand` run the injection channel stayed
empty on every turn, and no single turn had both.

The typo half turned out to be **three different behaviours**, and the case
text asserting one of them was wrong:

| Host | `mode: "atuo"` in the config file | Verified |
| --- | --- | --- |
| OpenClaw 1.x, OpenClaw 2.0 | **the host rejects it.** The manifest declares an enum, so the config fails validation before the plugin loads: `must be equal to one of the allowed values (allowed: "on_demand", "auto")` | on a real 2026.8.1 |
| DeepSeek Harness | **rejected at load** — the Config schema is a union of two literals | unit |
| Hermes, Raven, WorkBuddy | **narrowed to the default**, with no host schema to validate it against | unit |

Narrowing is deliberate: a typo should cost the deployment the mode it wanted,
not its retrieval. Narrowing *silently* is the defect — the deployment lands on
the opposite mode from the one it asked for, and 0.3.0 changed which mode the
default is. Fixed after `e9be3de`: all five narrowing sites now log what was
asked for and what ran.

Measured on a real host, with the value in the environment — which the host
does **not** validate, so this is the path that actually reaches the plugin:

```text
[plugins] [skillsearch] unknown mode "atuo"; running in on_demand
```

Reproduce with `scripts/e2e_openclaw.py --mode-typo atuo`, which writes the bad
value into the config, or `SKILLSEARCH_MODE=atuo` for the environment path.
